# Panorama Sales

Шахматка квартир для отдела продаж строительной компании Panorama.

Задача: менеджер на объекте показывает клиенту квартиру, клиент спрашивает
«а есть другие?» — и вместо звонка в офис менеджер открывает приложение и сразу
видит весь фонд, свободные варианты и кто чем занят.

## Что уже работает

- **Шахматка** по каждому ЖК: этажи × квартиры, переключение блоков, фильтр по
  комнатности и «только свободные».
- **Статус «В работе»** — ключевая механика. Перед выездом менеджер закрепляет
  за собой квартиру, остальные видят её занятой и не продают повторно.
- **Карточка квартиры**: планировка, характеристики, цена в долларах и сомах,
  рассрочка, история — кто и когда брал квартиру в работу.
- **Подбор** сразу по всем объектам компании: комнатность, бюджет, площадь.
- **Сделки** — свои показы и брони. **Клиенты** — запрос, автоподбор, звонок и
  WhatsApp.

## Структура

```
lib/
  core/
    config/app_config.dart        флаг useMockData, курс, длительность брони
    constants/                    цвета и типографика
    data/
      panorama_repository.dart        интерфейс источника данных
      mock_panorama_repository.dart   демо-фонд + имитация работы коллег
      api_panorama_repository.dart    реализация на REST (пути пока условные)
    models/                       ComplexModel, UnitModel, UnitStatus, ...
    network/api_client.dart       Dio
    providers/                    Riverpod: репозиторий, фонд, текущий менеджер
    router/app_router.dart
    theme/, utils/
  features/
    auth/         выбор менеджера (до появления авторизации)
    shell/        нижняя навигация
    complexes/    список ЖК
    board/        шахматка
    unit/         карточка квартиры, планировка, выбор клиента
    search/       подбор
    deals/        мои показы и брони
    clients/      клиенты
  shared/widgets/ общие элементы интерфейса
```

## Переход с моков на API

1. В `lib/core/config/app_config.dart` поставить `useMockData = false` и указать
   `apiBaseUrl`.
2. Сверить пути и формат ответа в `ApiPanoramaRepository` с реальным API.
3. Экраны менять не нужно — они работают только с интерфейсом
   `PanoramaRepository`.

Пока сервер не отдаёт события, `watchUnits()` перечитывает фонд раз в 15 секунд.
Когда появится WebSocket, заменить опрос на подписку — остальной код не заденет.

## Что ещё не сделано

- Авторизация менеджеров.
- Реальные фото ЖК, видов и чертежи планировок (сейчас схемы и заглушки).
- Оффлайн-режим: на стройке связь плохая, фонд стоит кэшировать локально.
- Отправка PDF-карточки клиенту (кнопка есть, генерации пока нет).

## Запуск

```bash
flutter pub get
```

```bash
flutter run
```

Приложение стартует на моках — сервер не нужен. Данные фонда генерируются
детерминированно, поэтому шахматка при каждом запуске выглядит одинаково.
Пока подключён мок, раз в 20 секунд «коллеги» берут квартиры в работу и
закрывают продажи — так видно, что шахматка живая.

## Проверка

```bash
flutter analyze
```

```bash
flutter test
```

Тесты проходят основные сценарии: выбор менеджера, открытие шахматки, взятие
квартиры в работу и заведение клиента через форму.

Важно: вызовы репозитория внутри `testWidgets` нужно оборачивать в
`tester.runAsync` — у мока внутри `Future.delayed`, и в fake-async зоне теста
такой таймер сам по себе не сработает, тест просто зависнет.
