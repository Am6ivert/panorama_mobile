# Panorama Sales

Шахматка квартир для отдела продаж строительной компании Panorama.

Рабочий инструмент отдела продаж: показывает весь фонд квартир в виде шахматки и
списка, фиксирует, кто и с каким клиентом работает по каждой квартире, ведёт
брони со сроками и уведомляет участников процесса об изменениях.

> **Ключевое ограничение (ТЗ 1.3):** приложение не хранит, не вычисляет и не
> отображает денежных значений ни в одном слое. Подбор — только по
> характеристикам: объект, блок, этаж, комнаты, площадь, вид, отделка, статус.

## Роли

- **Менеджер (продавец)** — смотрит фонд, берёт квартиры в работу, бронирует,
  ведёт своих клиентов и сделки. Видит все квартиры, но данные чужих клиентов
  ему недоступны.
- **Администратор** — управляет объектами и квартирами, создаёт учётные записи,
  подтверждает продажи, видит всю аналитику и журнал аудита.

Демо-доступ (пока не подключён backend с SMS-паролями):

| Роль          | Телефон             | Пароль |
|---------------|---------------------|--------|
| Администратор | +996 555 00-11-22   | `0000` |
| Менеджер      | +996 555 10-22-30   | `0000` |

## Что реализовано

- **Вход** по телефону и паролю; ролевая изоляция доступа. Экрана регистрации
  нет — учётные записи создаёт администратор.
- **Дашборд** — статистика фонда по шести статусам, активные клиенты/сделки/
  брони, истекающие брони и просроченные действия. Без денежных показателей.
- **Шахматка** по каждому ЖК: этажи × позиции, шесть статусов, фильтры
  (комнаты, статус, менеджер), переключатель «Шахматка / Список».
- **Статусы квартиры** (FR-06): Свободна · В работе · Бронь · Оформление ·
  Продана · Не для продажи (штриховка). Кнопки в карточке зависят от статуса и
  роли.
- **Бронирование** с обязательными данными клиента (фамилия, имя, телефон), срок
  брони 3 дня, лимит активных броней, автоснятие по истечении.
- **Реестр** всего фонда со вкладками (Все / Свободные / Мои / Брони / Истекают /
  Оформление), поиском и изоляцией данных клиентов.
- **Клиенты и сделки** со стадиями (Показ → Переговоры → Бронь → Оформление →
  Завершена / Отказ), звонок и WhatsApp.
- **Центр уведомлений** со счётчиком непрочитанных и deep link на карточку.
- **Админ-панель**: пользователи (создание, роли, блокировка), журнал аудита,
  мастер массового создания блока (FR-03), табличный редактор квартир (FR-04).

```

    config/app_config.dart        флаг useMockData, сроки брони, лимиты

  features/

    dashboard/    дашборд

    complexes/    список объектов → шахматка

    unit/         карточка квартиры, планировка, выбор клиента

  shared/widgets/ общие элементы интерфейса
```

## Переход с моков на API

1. В `lib/core/config/app_config.dart` поставить `useMockData = false` и указать
   `apiBaseUrl`.
2. Сверить пути и формат ответа в `ApiPanoramaRepository` с реальным API
   (версионирование пути `/api/v1/`).
3. Экраны менять не нужно — они работают только с интерфейсом
   `PanoramaRepository`.

Пока сервер не отдаёт события, `watchUnits()` перечитывает фонд раз в 15 секунд.
Когда появится WebSocket, заменить опрос на подписку — остальной код не заденет.

## Что вне объёма этого репозитория

Это мобильный клиент. Backend (REST API, PostgreSQL, FCM/APNs, S3, SMS) —
отдельный сервис. Клиент полностью работает на демо-данных (`MockPanoramaRepository`).
Реальные фото и чертежи, офлайн-кэш, экспорт XLSX и генерация PDF-карточки —
следующие итерации (v1.1–v1.2 по ТЗ).

## Запуск

```bash
flutter pub get
```

```bash
flutter run
```

Приложение стартует на моках — сервер не нужен. Данные фонда генерируются
детерминированно. Пока подключён мок, раз в 20 секунд «коллеги» берут квартиры в
работу и закрывают продажи — так видно, что шахматка живая.
